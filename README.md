# CT Checker — サイクルタイム測定アプリ

製造現場の作業時間（サイクルタイム）をその場で計測し、ばらつき・タクトタイムとの関係・
ラインのネックまですぐに確認できるブラウザアプリです。ライブラリ・サーバ・
インターネット接続は不要で、タブレットやスマートフォンのブラウザでそのまま使えます。

## 3階層の構造

```
工程（大工程）          … まとまりと配色の単位。最大 20
  ステーション（小工程） … ストップウォッチと計測の単位。全体で最大 60
    要素作業            … 1サイクル内の区切り。ステーションごとに最大 8
```

配色は8色までで、9工程目からは同じ色に**斜線**（9〜16番目は45°、17番目以降は135°）を
重ねて区別します（色だけに頼らないため。凡例・軸ラベル・明細表でも識別できます）。
工程が多いときは、計測画面と表示切替のチップが横スクロールの1行になります。

設定では**ステーションを足すだけ**で使い始められます（工程は分けたいときだけ追加）。
ステーションが20個あっても扱えるように、集計は **ライン全体 → 工程 → ステーション** の
3段階で掘り下げられます。計測画面も工程で絞り込めます。

| 見たいもの | 表示 |
| --- | --- |
| どこがネックか、工数はどう散らばっているか | **ライン全体** — ステーション別の山積み表＋工程ごとの工数内訳 |
| この工程の中のばらつき | **工程** — その工程のステーション比較＋推移 |
| このステーションの安定度・要素内訳 | **ステーション** — 推移・分布・要素作業別 |

## 構成を配る

まだ何も登録していないときは、**計測画面に「まだ工程が入っていません」の案内**が出ます。
そこのボタン、または設定タブの「用意された構成を読み込む」から選ぶだけで入ります。

Assy1〜Assy9 / Station1〜11 の構成は**アプリ本体に内蔵**しているので、
通信できない場所でも読み込めます。それ以外の構成は `presets/index.json` に登録すると
同じ一覧に並びます。
新しい構成を足すときは、アプリで組んで **JSON書き出し** したファイルを `presets/` に置き、
`presets/index.json` に1行追記して push してください。

### リンクで配る

`?preset=` に同じサイト内の構成ファイルを渡すと、開いたときに取り込めます。
現場の端末に「このリンクを開いて」と伝えるだけで同じ構成を配れます。

```
https://gaogao999.github.io/Ct-checker/?preset=presets/assy-line.json
```

iPhone では注意点があります。**Safari とホーム画面に追加したアプリは保存領域が別**です。
リンクは Safari で開くため、ホーム画面のアプリには入りません。ホーム画面のアプリに入れるときは、
アプリを開いて設定タブの「用意された構成を読み込む」から選んでください。

なお設定タブの一番下に動作中のバージョン（コミットID）を表示しています。
更新が届いているか確認するのに使えます。

## 使い方

`index.html` をブラウザで開くだけです。

```bash
# ローカルサーバ経由で開く場合（推奨）
python3 -m http.server 8000
# → http://localhost:8000/
```

ファイルを直接ダブルクリックして開いても動作します（Safari ではデータの自動保存が
無効になることがあるため、上のようにサーバ経由での利用を推奨します）。

現場端末に配布するときは、1ファイルにまとめたビルドが便利です。

```bash
node scripts/build-single.mjs   # → dist/ct-checker.html
```

`dist/ct-checker.html` は CSS・JS を内蔵した単一ファイルなので、USB メモリやメールで
配って、オフライン端末でそのまま開けます。

社内で URL を配りたい場合は、このリポジトリで GitHub Pages を有効にすれば
`index.html` がそのまま公開ページになります（Settings → Pages → Source: `main` / root）。
共有ページ（Claude Artifact）用に `<body>` の中身だけをまとめたビルドも用意しています。

```bash
node scripts/build-artifact.mjs # → dist/ct-checker.artifact.html
```

## 主な機能

**計測 — ふつうのストップウォッチと同じ操作**

| 操作 | 動き |
| --- | --- |
| カードをタップ | **スタート**。もう一度タップで**ストップ**（そこで時間が止まる） |
| 保存 | 止めた時間を1サイクルとして記録し、0 に戻る |
| リセット | 計測中の時間だけ 0 に戻す（記録済みのサイクルは消えません） |

- 止めずに**保存**を押すと、その時点で区切って計測を続けます（連続で測るとき）
- **ステーションごとに独立したストップウォッチ**。1つだけ動かす／止める、途中から別の
  ステーションを動かす、といった運用ができます（止めている間の時間は入りません）
- 表示中のステーションをまとめてスタート／ストップすることもできます
- 要素作業を登録したステーションは、タップするたびに要素の区切りになり、
  最後の要素で自動的にストップします
- 記録を間違えたら、明細タブの「直前のサイクルを取消」で戻せます
- 工程チップで計測画面を1工程に絞り込み（ステーションが多いときのスクロールを抑えます）
- 1サイクルを要素作業に分けた観測（ステーションごとに設定できます）
- **取消**（押し間違いを1つ戻す。サイクルをまたいで戻れます）
- **破棄**（イレギュラーが起きた進行中サイクルを捨てて測り直す）
- **一時停止 / 再開**（停止中の時間は計測に含まれません）
- 計測中は画面が消えないようスリープを抑止（対応ブラウザのみ）

**集計** — 表示切替で3階層を行き来できます

- ライン全体／工程：ネックステーション、ラインバランス効率、合計工数、必要ステーション数
  （合計工数 ÷ タクト）、タクト超過ステーション
- ステーション：平均・中央値・最小・最大・レンジ・標準偏差 σ・ばらつき CV、タクト比較
- 要素作業ごとの平均・最小・最大・σ・CV・構成比
- 異常値は明細の「除外」で統計から外せます。±2σ を超えるサイクルの一括除外にも対応

> ラインバランス効率＝各工程の平均の合計 ÷（工程数 × ネック工程の平均）×100。
> 100 % に近いほど工数の偏りが小さいことを示します。

**グラフ**（インライン SVG・ライト／ダーク両対応）

- ステーション別の平均サイクルタイム（山積み表。工程で色分け・区切り、最小〜最大のひげ、
  タクト線、ネックの ▲）
- 工程ごとの工数内訳（工程＝1本の積み上げ棒、1区切り＝1ステーションの平均）
- ステーション別サイクルタイムの推移（折れ線。配色スロットの都合で1度に8本まで）
- サイクルタイムの推移（要素作業ごとの積み上げ、平均線・タクト線、超過サイクルの ▲）
- サイクルタイムの分布（ヒストグラム）
- 要素作業ごとの平均時間（横棒＋最小〜最大のひげ）

**画面（iPhone 対応）**

- 下部タブで「計測 / 集計 / 明細 / 設定」を切り替え。**左右スワイプ**でも移動できます
  （表の横スクロール中と入力欄では無効。スワイプ直後の誤タップも抑止しています）
- カードは1枚 約120px。名前・経過・操作ラベルまで含めた**上半分がまるごとラップボタン**で、
  停止・取消・破棄は下の細い行にまとめています。狭い画面では自動で2列に並びます
- ステーションが9個以上あるときは1行1ステーションの**リスト表示**に自動で切り替わり、
  行のどこを押してもラップできます（カード／リストは手動でも切替可）
- ステーションが1つだけの工程は見出しを省き、工程名をカード内に小さく表示します
- セーフエリア対応、計測中はヘッダーとタブに稼働状況を表示

**データ（消えないための仕組み）**

- 入力内容と計測結果はブラウザに自動保存され、閉じても復元されます
- **全データ消去・読込・JSON取り込みの直前に自動でバックアップ**を取り、「保存した測定」から
  いつでも戻せます（自動保存は上限を超えても手動保存より先に消えます）
- **保存形式にバージョン番号（`schema`）を持たせ、自分より新しいデータには書き込みません。**
  古いキャッシュのコードが新しいデータを壊すのを防ぎます（検出時は画面上部で再読み込みを促します）
- 起動時に前回の内容と比べ、**ステーション数や記録数が減っていたら古いほうを自動退避**します
  （「保存した測定」に「復元用」として並び、読込で戻せます）
- 壊れたデータでも起動できるようにし、読めなかった元データは退避します
- `navigator.storage.persist()` で端末にデータを残すよう要求します
  （ホーム画面に追加した PWA では特に効果があります）
- 保存に失敗した場合は画面上で警告し、JSON 退避を促します
- 名前を付けて複数の測定を保存し、読み込み・比較・削除ができます
- CSV 書き出し（Excel でそのまま開ける UTF-8 BOM 付き）／ JSON の書き出し・読み込み
  - ライン全体／工程表示：ステーション別マトリクス＋ステーション別統計＋工程サマリ＋バランス効率
  - ステーション表示：サイクル明細＋要素別統計

## キーボード操作

| キー | 動作 |
| --- | --- |
| `Space` / `Enter` | 先頭ステーションのスタート / ストップ |
| `1` … `9` | カード右上の番号のステーションのスタート / ストップ |
| `S` | 保存（1サイクルとして記録） |
| `P` | 表示中のステーションをまとめてスタート / ストップ |
| `Z` | 直前のサイクルを取消 |

## 計測データの持ち方

計測は「そのステーションのストップウォッチの累積時間（ms）」の区切り位置だけを記録します。
時計はステーションごとに独立していて、止めている間は進みません。

```js
group   = { id: 'a1b…', name: '組立' }           // 工程（大工程）
station = {
  id: 'k3f…', groupId: 'a1b…', name: 'ねじ締め',
  accBase: 128400,            // このステーションのストップウォッチの累積(ms)
  started: true,              // 一度でも開始したか
  elements: [{ id, name }],   // 1個なら1タップで1サイクル
  cycles: [{
    startAcc: 12345,          // サイクル開始時点の累積経過(ms)
    marks:    [15000, 22000], // 各要素作業を終えた時点の累積経過(ms)
    excluded: false,          // 統計から除外するか
    note:     '',             // メモ
    at:       '2026-08-19T…'  // 記録時刻
  }],
  cycleStart: 22000,          // 計測中サイクルの開始
  pending:    []              // 計測中サイクルの確定済み区切り
}
```

各要素の所要時間は隣り合う区切りの差分として計算されるため、取り消し操作をしても
時間のつじつまが合わなくなりません。旧バージョンの保存データ（単一工程／複数工程・共通の
時計）は、読み込み時に既存の工程がステーションとして自動で取り込まれます。

配色はカテゴリカル8色を工程に割り当て、ステーションは同じ工程の色を共有します
（個々の識別は軸ラベルと明細表が担います）。色を循環させないための設計です。

保存先は同一ブラウザの `localStorage` のみで、外部への送信は一切ありません
（キー: `ct-checker:v1` / `ct-checker:sessions:v1` / `ct-checker:theme`）。
端末を移すときは JSON で書き出してください。

## ファイル構成

```
index.html                 画面
assets/styles.css          スタイル（ライト／ダークのトークン定義を含む）
assets/app.js              計測ロジック・集計・SVG グラフ描画
manifest.webmanifest       PWA マニフェスト（ホーム画面に追加用）
sw.js                      サービスワーカー（オフライン表示）
icons/                     アプリアイコン
scripts/build-single.mjs   配布用の単一 HTML を生成

```
